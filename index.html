첫 실습 · 계속 생성되는 작은 빛

목표: 화면에 파티클이 계속 생성되고 약 2초 뒤 사라지는 것을 확인합니다. 아래 값은 학습용 시작값입니다. UE 5.x에서는 템플릿과 입력 이름이 버전에 따라 다를 수 있습니다.

  1. 시스템 만들기. 콘텐츠 브라우저에서 Niagara System을 만들고 Sprite Renderer가 포함된 기본 이미터 템플릿을 선택합니다. 이름을 NS_Practice_Sprite로 저장하고 엽니다. 템플릿이 다르면 아래 스택에 필요한 항목을 확인해 추가하세요.
  2. 추가하는 위치 찾기. 이미터를 선택하고 Selection/스택 패널에서 각 그룹의 ＋를 누릅니다. 아래 영문 모듈명으로 검색합니다. 이미 있는 모듈은 값을 수정하고 중복으로 추가하지 않습니다.
  3. 가장 작은 스택 맞추기. 첫 실습에서는 템플릿의 추가 힘·속도·충돌 모듈을 잠시 꺼서 변수를 줄입니다. 다음 표를 위에서 아래로 확인합니다.

  1. 재생하고 확인하기. 컴파일 오류를 해결한 뒤 미리보기 타임라인을 재시작합니다. 점들이 구형 영역에 계속 나타나는지 봅니다. 이 단계에서는 이동하지 않아도 정상입니다.
  2. 한 번에 하나만 바꾸기. Spawn Rate를 20 → 40으로 바꾸면 더 조밀해지는지, Lifetime을 2 → 1로 바꾸면 더 빨리 사라지는지 비교합니다.
  3. 레벨에서도 확인하기. 저장한 시스템을 레벨에 배치하고 재생합니다. 미리보기와 다르면 카메라·노출·스케일·활성화 상태를 확인합니다.
성공 기준 · 일정 시간 뒤 파티클 수가 계속 누적되지 않습니다. 컬링이나 추가 스폰이 없는 정상 상태라면 약 20 × 2 = 40개가 유지됩니다. 화면에 안 보이면 문제 해결로 이동하세요.

다음 실습 · 움직임과 사라짐

움직임: Particle Spawn에서 Add Velocity를 찾아 위쪽 속도를 설정합니다. 해당 이름이 없으면 모듈 검색에서 velocity로 찾아 현재 엔진의 동등한 모듈을 확인하세요. Particle Update에는 Solve Forces and Velocity가 필요합니다. 힘을 추가한다면 일반적으로 솔버 앞에서 계산하며, 편집기의 의존성 경고를 우선 확인합니다.

페이드: Scale Color의 알파를 수명에 따라 1 → 0으로 바꿉니다. 머티리얼이 Particle Color의 알파를 Opacity에 반영해야 합니다. 커브 사전에서 모양을 비교하세요.

성공 기준 · 위로 이동하고 끝부분에서 부드럽게 사라집니다. 작동하지 않으면 속도 → 솔버 → 알파 커브 → 머티리얼 순서로 한 항목씩 확인합니다.

헷갈리는 개념 4가지

  • System / Emitter / Particle: 이펙트 전체 / 생성기 한 개 / 생성된 입자 한 개. 불과 연기를 서로 다른 이미터로 구성할 수 있습니다.
  • Spawn / Update: 태어날 때 한 번 설정 / 살아 있는 동안 매 프레임 갱신. 시작 크기는 Initialize Particle, 시간에 따른 변화는 Update 모듈을 확인합니다.
  • Lifetime / NormalizedAge: 생존 시간(초) / 생애 진행률(0~1). 2초 수명인 입자의 중간 지점은 1초이며 NormalizedAge는 0.5입니다.
  • Local / World Space: 이펙트와 함께 움직일지, 월드에 남을지 정하는 기준입니다. 캐릭터가 움직일 때 궤적까지 따라오면 Local Space 설정을 확인하세요.

이 매뉴얼을 쓰는 방법

전체 검색은 모듈·목표·레시피·머티리얼·용어·팁·진단·레퍼런스·학습 내용을 함께 찾습니다. 검색 결과를 누르면 해당 항목으로 이동합니다. 주소의 # 뒤에는 현재 항목이 저장되어 북마크와 뒤로 가기가 가능합니다. 모듈의 ★·메모·학습 진행률은 브라우저에 저장됩니다. 기존 파일에서 내 데이터 백업 후 새 파일에서 가져오면 학습 기록을 옮길 수 있습니다.

본문과 검색은 오프라인 동작합니다. 공식 문서 링크는 인터넷이 필요합니다. 원본의 71개 모듈과 전체 탭을 유지했으며, 모든 엔진 기능을 망라하거나 프로젝트에서 실행 검증한 자료는 아닙니다. 수치는 출발점으로 사용하고 실제 프로젝트에서 확인하세요.

확인 자료: Epic · Sprite 효과 생성 · Epic · Particle Update 레퍼런스 (검토: 2026-09-07). 기존 버전별 요약은 프로젝트 엔진의 릴리즈 노트와 별도 대조가 필요합니다.

영문 이름, 한글 발음, 원하는 효과, 증상으로 찾으세요. 여러 단어를 입력하면 모두 포함하는 내용을 찾습니다.

사용법 — 영문명·한글 발음·기능 키워드·유니티 모듈명 무엇으로든 검색됩니다. 카드의 ★로 북마크, 비교 버튼으로 두 모듈을 나란히 비교할 수 있습니다. 보라색 배지는 버전 관련 노트입니다.
🔍
역방향 검색 — "위로 떠오르게 하고 싶어", "빨려들게", "따라다니게"처럼 만들고 싶은 결과로 검색하면 필요한 모듈 조합을 알려줍니다. 초록색 모듈명을 클릭하면 상세 설명으로 이동합니다.
🎯
레시피 빌더 — 이펙트 유형을 선택하면 이미터 구성과 스택 순서(위→아래 실행 순서 그대로)를 통째로 보여줍니다. 모듈명을 클릭하면 상세 설명으로 이동합니다. 수치는 시작점이며 프로젝트 스케일에 맞게 조절하세요.
진단 마법사 — 증상을 클릭으로 골라가면 원인과 해결 모듈에 도달합니다. 검색할 키워드를 몰라도 됩니다. 결과의 초록 모듈명을 클릭하면 상세 설명으로 이동합니다.

그래도 해결이 안 될 때 (만능 4단계)

  • 어트리뷰트 스프레드시트(창 메뉴)에서 파티클의 Position·Color·Age 실제 값을 확인 — 이상한 값을 만드는 모듈을 역추적합니다.
  • 이미터 격리(Isolate)로 문제 이미터만 단독 재생해 범위를 좁힙니다.
  • 모듈 이분 탐색 — 모듈 절반을 체크박스로 끄고 재생, 문제가 남은 쪽을 다시 반으로. 3~4번이면 원인 모듈을 찾습니다.
  • 같은 템플릿을 새로 만들어 정상 동작본과 스택을 비교합니다.
유니티(Shuriken)에서 넘어오셨나요? — 유니티 파티클 시스템 모듈명을 그대로 입력하면 나이아가라에서 동일한 효과를 내는 방법을 알려줍니다. 예: color over lifetime, bursts, trails
🔍

사고방식 전환 핵심 3가지

  • 모듈 = 체크박스가 아니라 '추가'하는 것. 유니티는 고정된 모듈 목록을 켜고 끄지만, 나이아가라는 빈 스택에 필요한 모듈을 + 버튼으로 추가하고 순서도 바꿉니다. 순서가 결과에 영향을 줍니다(예: 힘 모듈들은 Solve Forces and Velocity보다 위에).
  • "over Lifetime" = Normalized Age 커브. 유니티의 수명 기반 커브들은 나이아가라에서 Particles.NormalizedAge(0~1)를 입력으로 쓰는 Float/Vector/Color from Curve 다이내믹 인풋으로 구현됩니다. Scale Color, Scale Sprite Size가 이미 이 구조를 내장하고 있습니다.
  • 머티리얼이 절반이다. 유니티의 파티클 셰이더 역할을 언리얼 머티리얼이 합니다. 파티클 색을 쓰려면 머티리얼에 Particle Color 노드를, 커스텀 값은 Dynamic Parameter 노드를 반드시 연결해야 합니다. 색이 안 바뀌면 90%는 이것 때문입니다. → 자세한 내용은 머티리얼 탭.
파티클 머티리얼 노드 사전 — 이펙트 머티리얼에서 실제로 쓰는 노드와 세팅만 모았습니다. 나이아가라 실력의 절반은 머티리얼에서 나옵니다.
🔍
실무 레퍼런스 — 다이내믹 인풋·스크래치 패드에서 쓰는 파티클 어트리뷰트, 블루프린트 연동 함수, 콘솔 명령을 한곳에 모았습니다. 함수·명령 이름은 엔진 버전에 따라 일부 다를 수 있습니다.
🔍
